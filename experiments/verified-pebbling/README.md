# AEIG 抜本的解決研究：容量制約付き再計算の厳密解法

SDK に存在する「計算結果を保持するか、解放して後で再計算するか」という設計課題を、有限 DAG の数学モデルに定式化した研究パッケージです。最小総計算費用の実行列、または実行不能性を求め、探索プログラムとは独立した検証器で証明書を確認します。

**世界未解決問題を解決した成果ではありません。** 世界最高難度という認定もしていません。公開 SDK の契約から正当に結び付けられる既知の困難な問題に対し、前提を限定した完全な解法と検証可能な成果を用意したものです。ユーザーの絶対条件は未達です。

SDK は計算キャッシュの全入力をキーに含め、計算結果の総メモリ量を purge heuristic に渡す契約を持ちます。この契約は研究の動機を支持します。AE の非公開 scheduler がこのモデルと同じであることや、現在の実装に最適化の欠陥があることの証拠ではありません。

数学的には graph pebbling、計算複雑性、time–space tradeoff、有限状態の検証に接続します。一般の標準 pebbling の PSPACE 完全性は既知の結果です。本実装の指数時間探索がこの難しさを解消したという主張はしません。

## 再現方法

Python 3.10 以降の標準ライブラリのみを使います。リポジトリのルートから実行します。以下の rtk はこの作業環境のコマンド規約です。他の環境では Python を直接実行できます。

~~~powershell
rtk proxy python experiments/verified-pebbling/run_experiment.py
~~~

この実験はテスト後、4・5・6・7 MiB のモデルと証明書、検証結果を results に書き出します。After Effects を起動せず、プロジェクト、プラグイン、設定、L5 観測データを変更しません。

個別に探索と検証を実行するには次を使います。

~~~powershell
rtk proxy python experiments/verified-pebbling/solver.py experiments/verified-pebbling/fixtures/recompute.json --output experiments/verified-pebbling/results/manual.certificate.json
rtk proxy python experiments/verified-pebbling/verify.py experiments/verified-pebbling/fixtures/recompute.json experiments/verified-pebbling/results/manual.certificate.json
~~~

探索の終了コードは、証明書生成成功が 0、入力や入出力エラーが 2、探索上限による未確定が 3 です。検証器は証明書が妥当なら 0、不正または未確定なら 1 を返します。実行不能を正しく証明した場合、検証器の結果は成功です。

## 合成例の結論

| 使用可能量 | 厳密な結果 | 最小計算費用 |
|---|---|---:|
| 4 MiB | 必須の作業領域が入らず実行不能 | — |
| 5 MiB | source を一度解放して再計算すれば完了 | 29 |
| 6 MiB | 同じく source の再計算が必要 | 29 |
| 7 MiB | 各ノードを一度だけ計算して完了 | 26 |

費用は入力で与えた抽象単位であり、秒数や AE の実測値ではありません。MiB もモデル内の占有量です。実験中にその容量の画像を確保して計測した値ではありません。

5 MiB の場合、workspace は analysis 1 MiB、出力 1 MiB、一時領域 3 MiB の合計 5 MiB を必要とします。source 2 MiB は保持できず、後段 composite のために再計算が必要です。「全ノードを一度だけ計算する」方針では失敗する有限例を、再計算を許した最適列で解決しています。

別に実装した集合ベースの Bellman–Ford 全探索と、437 個の DAG・容量の組合せおよび合計320 個の乱数 seed 固定の重み付きモデルで照合します。改ざん証明書、誤った入力、ゼロ容量、複数目標、一時作業領域、探索打切りも検査します。toy computation の出力一致は確認しますが、AE 画像の一致試験ではありません。

## 入力契約

入力 JSON のフィールドは、fixture と同じものをすべて明示します。

- budget_bytes：使用可能量。0 以上の整数。
- targets：最後に同時に保持するノード ID の配列。
- nodes：id、deps、bytes、cost、scratch_bytes を持つノードの配列。
- bytes と scratch_bytes は 0 以上、cost は 1 以上の整数。真偽値や小数は受け付けません。
- 同一 ID、重複依存、循環、存在しない依存、未定義フィールドを拒否します。

保持済み集合 S からの計算では、「S の占有量 + 新規出力 + 一時作業領域」が予算以下であることを要求します。入力を上書きする操作ではありません。解放は別操作で、費用ゼロです。

全ノードが純粋・決定的で、すべての依存が既知、入力 snapshot が不変、割当の情報が完全である必要があります。解放時に別スレッドの参照や receipt の pin がある状況は扱いません。近似的なメモリ見積りだけでは実機の容量保証になりません。

## 証明の要点

状態は保持中ノードの部分集合です。最大 2^n 個の状態を有限グラフにし、非負費用の最短経路を求めます。

旧版（証明書 v1）は、開始状態を含む集合の全合法遷移閉包と、各辺 S -> U に対する d(U) <= d(S) + cost を検査します。閉じた集合内に目標が一つもなければ実行不能です。旧方式は --full-closure で再現でき、既存の証明書も検証できます。

新版（証明書 v2）は、候補の費用 C より小さい値を持つ状態だけを記録し、省略状態の値をすべて C と定義します。記録した状態からの全合法辺に同じ不等式を検査し、目標状態の値を C にします。省略状態からの辺の不等式は、費用が非負なので自動的に成立します。経路に沿って不等式を足せば、どの成功経路の費用も C 以上です。費用 C の合法経路も再実行して確かめれば、最適性が証明できます。

13 ノードの比較用合成モデルでは、従来8192 状態だった証明が1 状態になり、最適費用は同じ1 です。一方、改良が効かず256 状態が必要な反例も試験しています。指数的な最悪ケースを解消したわけではありません。無料の解放で安い状態へ逃げられる抜け道も、検証器が明示的に検査します。

探索器の結論を信用して受け入れる設計ではありません。ただし、Python 実行系と検証器自体まで形式検証したものではありません。

## 適用限界

探索上限は通常100,000 状態、指定可能な上限は250,000 状態、ノード数は最大63です。証明成立前の上限到達は inconclusive（未確定）であり、実行不能ではありません。上限は証明に記載する状態だけでなく、探索中に保持した状態にも適用します。指数的に増えるため、全コンポジションを高速に最適化できる保証はありません。

ホストのメモリ予算は探索器の使用メモリとは別です。実行計画を自作プラグインへ適用する場合は、ホストと他スレッドの予約量、allocator の overhead、receipt の寿命、キャンセル、外部状態、CPU/GPU 差を別途扱う必要があります。公開 Compute Cache API を通じて、ホスト内部の解放順を自由に置き換えられるわけではありません。

AE の実機での高速化、非公開実装の修正、完全な依存 DAG の自動抽出は未実施です。既存の研究ステータスや本番データを、この合成実験だけで昇格させていません。
